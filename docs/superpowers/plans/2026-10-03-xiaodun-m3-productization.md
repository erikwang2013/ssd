# 小盾 M3「产品化」：可上架销售的桌面 1.0 立项计划（草案）

> **状态：立项级草案（plan-m3 起草，2026-10-03）。执行前需细化轮**——本文件只定目标、裁定候选、任务边界、验收定义、接口与风险；每个任务进入实施前由 spec 代理产出逐件任务书（头部裁定/纪律/前置 → Files → Task 步含测试钉与门禁 → 验收定义 → 执行记录节），粒度对齐 `docs/superpowers/plans/2026-10-02-xiaodun-m1e-tail-platforms.md`。
> **标注「需产品决策」的裁定在落定前不得进入 T1/T2 细化轮**；技术裁定由细化轮前的预研（§3）给出决策输入。

**Goal:** 把 M1/M2 的「能用」变成「能卖」——免费预览/付费导出的许可体系 + APFS（含快照）引擎 + 性能打磨 + 签名/申报/合规闭环，产出三平台**可上架销售的桌面 1.0**（设计文档 §7 M3 行）。

**纪律（沿用 M1 惯例）:**
- 一切真机/真授权/真支付路径标注「未验证（需真机）」；CI 能验的必须验（fixture、契约 golden、门禁、打包冒烟）。
- 只读铁律与「不写回源设备」不因商业化放松；**付费门禁加在 daemon/`--export-worker`（RPC 面，worker 权威），不加在 UI**——与目标三重校验同一模式。
- 文案与设计 §2.2/§9 诚实边界一致：付费卖的是**导出能力**，不卖「恢复成功率」承诺；试用限额不得中断扫描/预览体验。
- 量化前后对照沿用 M1c 先例格式（JPEG 预读 20046→2 次读、落库 139→>8000 条/秒）。

**前置（M2 交付面；未达则 M3 相应任务顺延，见 §7）:** 契约 v1.x 稳定、NTFS/ext4 引擎可用、macOS 签名+公证链落地、三平台提权入口接通（含 Windows 首页入口）、-32006 在 Win/macOS 闭合。

## 1. 目标与范围

### 1.1 四个交付物（对齐路线图 M3 行）

| # | 交付物 | 出口判据（摘要） |
|---|---|---|
| A | 付费导出与许可体系 | 购买→签发→激活→离线校验→导出解锁/配额强制全链路可演示；退款/吊销/换机边界如实标注 |
| B | APFS（含快照） | macOS 真机「快照→删除→恢复逐字节」；合成 fixture 恢复率门禁进 CI |
| C | 性能打磨 | 设计 §4.6 硬指标达成（扫描吞吐 ≥ 顺序读 70%、百万级结果翻页流畅）+ 量化目标门禁化 |
| D | 可上架销售 | 三平台签名/公证产物 + 杀软申报 + 上架合规材料 + 更新机制 |

### 1.2 非目标（明示排除，写进文档）

- 移动线（M4）与专业版（M5）。
- **APFS 加密卷（FileVault）不支持**——无密钥不可读，文案诚实说明（细化轮核实「挂载态经块设备读明文」是否可作后门路径，默认不做）。
- **桌面应用商店（MAS / Microsoft Store）**：MAS 沙箱与特权 daemon + raw 设备访问结构性冲突（设计 §5.1 提权模型不兼容）；MS Store 同样限制特权行为。v1.0 明确排除并把论证入档（D3）；未来若上商店需独立产品形态。
- 自动更新：v1.0 手动检查更新（D4），自动更新归 M4/M5（依赖签名链稳定）。
- 在线反盗版军备竞赛（D6）：本地工具防破解上限低，轻量防护 + 诚实边界，不做多位置/指纹纠缠。

### T1 授权核心与强制执行点（Rust）

- **交付**：`xd-core` 许可模块（载荷解析 + 离线签名验证 + 状态机：无证/试用/已授权/过期）；试用配额记账（件数/字节）；daemon 与 `--export-worker` **双层强制**（worker 权威，同目标三重校验模式）；契约 v1.x 增量（`license.status`/`license.activate` + 错误码——编号细化轮定，现止于 -32010）；license 状态文件落 XDG（**提权/降权两态可读性**——参考 portfile 属主交还教训，root daemon 与降权 worker 都要能读）。
- **依赖**：D2/D6 落定；PR-2。
- **验收**：离线校验单测（篡改/过期/错签名全拒）；配额强制在 daemon 面（**UI 绕过测试**：直连 TCP 会话请求 export.start 超配额 → 拒绝）；契约 golden 双侧；过期/试用边界文案；明文声明防护上限（D6）。
- **估**：3-4 人周。

### T2 购买/激活 UX 与交付面（UI + 产品）

- **交付**：激活页（输入/粘贴 license、状态、试用余量）；结果/恢复页付费引导（诚实口径，对照 §2.2）；购买入口（外链 MoR 页面）；官网交付面最小化（落地页/FAQ/退款政策——产品侧）。
- **依赖**：D1/D3/D5 落定；T1。
- **验收**：全链路 widget/集成测试（试用→限额→激活→解锁）；文案审查对照设计 §2.2/§9。
- **估**：2-3 人周。

### T3 APFS 只读引擎 v1（存活 + 删除尽力）

- **交付**：`xd-fs-apfs`——容器（NXSB/checkpoint/omap 解析）、卷（APSB）、FS B-tree 遍历（inode/dirent/extent 记录）、存活文件枚举 + 删除项尽力识别（质量分级接入）；`scan.start` fs 探测接入（`apfs`）；**加密卷检测 → 明确拒绝**（错误码+文案，不得静默空结果）。
- **依赖**：PR-1（fixtures 就绪）。**无 M2 硬依赖**——fixture 开发环是普通文件镜像，真机 /dev/rdisk 路径才需 TCC/FDA 结论。
- **验收**：合成镜像恢复率门禁（存活 100%、删除项按实测基线——**未知≠零**口径，M1e T3 先例）；fuzz 无 panic；只读哈希不变断言；真机读标「未验证（需真机）」。
- **估**：6-8 人周。

### T4 APFS 快照恢复

- **交付**：快照枚举（snap_meta 树）→ 按快照 xid 读取历史卷视图 → 从快照恢复文件（逐字节）；UI 呈现「快照副本可用」信号；质量分级新增「快照（完整）」档。
- **依赖**：T3。
- **验收**：合成镜像「写→快照→删→恢复逐字节」门禁；多快照选择；无快照卷回落 T3 且文案切换。
- **估**：3-4 人周。

### T5 APFS fixtures 与 CI 工程化

- **交付**：fixture 生成脚本（PR-1 选定途径）+ 入库策略；CI 解析/恢复率/fuzz job；大镜像长跑（可选 job）。
- **依赖**：PR-1。
- **验收**：生成确定性（同脚本同镜像哈希）；镜像体积与 CI 时长预算入档。

### T6 性能打磨（全链路）

- **交付**：依 PR-5 基线逐项优化——扫描吞吐（设计 §4.6 ≥ 顺序读 70%）、雕刻吞吐、落库/查询（保持 ≥8000 条/秒）、导出吞吐、UI 百万级翻页（虚拟化 + 分页，P95 目标细化轮定）、内存上界；每项配 CI 门禁（D8 形态）。

## 5. 出口标准（「可上架销售的桌面 1.0」判据）

1. **产物**：三平台签名/公证安装包发布（macOS 公证+staple、Gatekeeper 首开无警告；Windows 签名、SmartScreen 无「未知发布者」）；校验和清单与发布说明齐备。
2. **许可**：购买→签发→激活→离线校验→导出解锁全链路 e2e（含 UI 绕过防护测试）；试用限额 daemon 面强制；退款/吊销/换机边界如实标注。
3. **APFS**：macOS 真机「快照→删除→恢复逐字节」演示通过；合成 fixture 恢复率门禁进 CI；加密卷/无快照场景文案诚实。
4. **性能**：设计 §4.6 硬指标（扫描吞吐 ≥ 顺序读 70%、1M 结果翻页流畅）+ 细化轮数值全部达成且门禁进 CI 有牙。
5. **杀软/合规**：主流 AV 申报完成（误报清零或如实记录残留）；EULA/隐私政策随包发布；「联网点 = 更新检查（可关）+ 激活（如在线）」成立。
6. **测试**：全矩阵 CI 绿（3 OS workspace + flutter + deb + e2e + packaging + bench）；未验证边界总表更新并入 README。
7. **文档**：README 状态、设计文档实现注记、本计划执行记录（格式同 M1e）。
