# 小盾 M5「专业版」实施计划（立项级）

> **本文件是立项级草稿（charter），不是可执行计划。** 每个任务在开工前必须先产出自己的
> 细化计划（沿用 M1a/M1b/M1e 的「计划即规格」模板：Files / Step / 全代码要点 / Done 判据），
> 再走 impl → spec → qual 三评审管线。本文件只钉**范围、裁定候选、任务边界、出口标准与风险**。
>
> 状态：**待产品决策**（§5 开放项）→ 裁定冻结 → 逐任务细化轮 → 实施。
> 纪律：一切真机路径（真设备写、真提权下写授权、真坏道盘）在文档与注释中标注
> **「未验证（需真机）」**；CI 能验的（结构性写面检查、环回设备写、合成镜像全链路、
> 确认令牌协议、审计落盘）**必须验**。

**Goal:** 交付「专业版」三件套——**磁盘镜像**（整盘/分区制作、校验、写回介质）、
**扇区编辑**（十六进制查看/编辑，含写路径）、**批量工单**（多介质扫描→筛选→导出编排），
外加 `xd-cli` 专业版命令行（设计 §3.1 第 5 条「同一 core 可直接复用为专业版 CLI」）。
M5 是产品**第一次拥有对块设备的写能力**——本计划的重心不是功能清单，而是
**写路径的安全模型**与**只读铁律的边界裁定**。

**前置：** M1 已完整合入（只读引擎/daemon/UI/三平台平台层/打包）；M2 的 Windows 卷号比较与
macOS IOKit 盘/分区归属（§4 依赖 D1，**M5 准入条件**，见裁定 A5）；M3 的许可激活（专业版门禁，可选）。

## 0. 现状事实（写作基线，全部已落地可查）

| 事实 | 出处 |
|---|---|
| `BlockDevice` trait **零写接口**，只读铁律是编译期保证 | `crates/xd-device/src/lib.rs:62` |
| 设备一律 `O_RDONLY` / `GENERIC_READ` 打开 | `linux.rs`/`macos.rs`/`windows.rs` 打开臂 |
| Linux `uaccess` 给的是 **rw ACL**——"只读"不在权限层，在类型 + open flag | security §2 |
| 唯一既有写路径 = **导出**：降权子进程 `--export-worker`（root → 调用者身份后写文件） | security §6、`xd-daemon/src/export_worker.rs` |
| 同盘校验 -32006 两道（`st_dev`+盘级祖先），**sysfs 解析失败 fail-open** | security §6、`xd-core/src/export.rs:89` |
| 既有已知缺口：Windows 无 `st_rdev`（恒 `None`）、macOS 整盘源 vs 分区目标不拦 | security §8/§9、README「已知限制」 |
| 工单/结果持久化已有 SQLite（`tasks`/`entries`）与检查点续跑机制 | `xd-core/src/store.rs`、`scan_task.rs` |
| `xd-cli` 仅在设计文档预留，**crate 不存在** | 设计 §3.2 |

**M5 三件事的风险分层（这是全计划的骨架）：**

| 功能 | 读什么 | 写什么 | 风险级 |
|---|---|---|---|
| 磁盘镜像·制作 | 源设备（只读） | 镜像**文件** | 低（沿用导出的目标校验即可） |
| 磁盘镜像·**写回介质** | 镜像文件 | **块设备** | **高（首次设备写，不可逆）** |
| **扇区编辑** | 设备/镜像分片 | **块设备**（单扇区级） | **高（任意偏移写，不可逆）** |
| 批量工单 | 多介质（只读） | 目标目录（文件） | 低（编排层，无新写面） |

即：**只有两处设备写**。全部安全投入集中在这两处，其余是编排与呈现。

## 1. 关键裁定候选（§1.A 为计划核心，全部需产品决策后冻结）

### A. 只读铁律的作用域 + 设备写路径安全模型 ★

**A0「作用域」裁定（推荐）：** 只读铁律的原文是「**源设备句柄一律只读打开**」（设计 §4.4.1），
其规范对象是**恢复流水线对源介质的访问**，目的是「写错一次毁掉用户数据」。据此：

- **镜像制作**读取源介质，**完整受只读铁律约束**（源侧零写；「扫描后源哈希不变」的 CI 门禁
  **扩展**到镜像制作路径）。
- 「写回介质」「扇区写」的规范对象是**用户显式指定的目标介质**，此时工具角色从"恢复器"
  变为"写工具"——铁律在此不适用，但**必须有一条与恢复路径结构性隔离的新通道**。
- 铁律**不得**被解读为"进程永不写盘"（导出早已写盘）；也**不得**被静默削弱为
  "某处加个 if 就能写设备"。

**由此产生的替代不变量（M5 的核心安全命题）：**
> **「恢复路径不可达写能力」**——从 scan / preview / export / image-create 任何代码路径
> 都无法触达设备写：无类型转换、无共享句柄、RPC 方法族分离、写进程独立。
> 该不可达性**由 CI 结构检查钉死**，不靠评审记忆。

**A1 代码面隔离（推荐）**

- 设备写能力进**新模块**（建议 `crates/xd-device/src/write/`），导出**新类型**
  （如 `SectorWriter`），与 `BlockDevice` **无任何互转**（无 `From`/`as_writable`/共享 fd）。
- CI 硬门禁：**"设备写面清单"结构断言**——全仓对块设备以可写方式打开的代码只在白名单文件集合内
  （扫描 `O_RDWR`/`O_WRONLY`/`GENERIC_WRITE`/`WriteFile`/`write_at` 的设备打开臂）；
  白名单外的命中即红。等价于把「只读铁律」从一句口号变成一条可执行断言。
- 另加一条**符号级**门禁（低成本高确定性）：`xd-daemon` 二进制符号表内**零设备写 API 符号**（见 A2）。

**A2 进程面隔离（推荐：独立短命 writer 二进制）**

- **两个候选**：
  - **(a) 独立小二进制 `xd-writer`**（推荐）：长命 daemon **二进制里根本没有写代码**——
    「daemon 不可能写设备」成为可 grep、可 nm 验证的事实。代价 = 打包多一个文件
    （Windows zip / macOS `.app` `Contents/MacOS` / deb 各 +1；macOS 嵌套可执行的签名归属
    与 xd-daemon 同款，归 M2 签名轮一并处理）。
  - **(b) 自 spawn `--write-worker`**（先例一致：`--export-worker`）：打包面零增量，
    但 daemon 二进制含写代码，隔离性弱一档。
- 两者共同语义：**写是单次、短命、可 kill 的操作**；长命进程不持有可写设备句柄；
  取消 = 杀 worker（已写部分保留并如实报告——半写是写路径的合法状态，必须明示）。
- 与导出的**方向相反**：导出 worker 是 root→降权（写文件）；writer 是**普通用户优先**——
  Linux `uaccess` 的 rw ACL 意味着可移动介质**本就无需 root**；writer **不得主动提权**，
  打不开就以专门错误码拒绝并说明原因（macOS/Windows 的提权写见 A3）。

**A3 权限面（推荐三条）**

1. **长命 root daemon 不写设备**：所有设备写由 writer 承担；writer 继承调用者环境，
   **不自行提权**（`pkexec`/`Start-Process`/`osascript` 只用于拉起只读 daemon，不用于 writer）。
2. **平台差异如实处理**：Linux 可移动介质免提权可写；macOS `/dev/diskN` 与 Windows 物理盘
   需管理员/FDA，此时 writer 只能由已提权的 daemon 派生（继承 root）——**这是 M5 唯一的
   root 写路径**，故对其叠加 A4 的闸门 1-4 全部（含强制撤销快照），并在文档与 UI 明示。
3. **可移动介质优先**：`removable == true`（或镜像文件）为默认可写目标；对内置盘/系统盘
   走 A4 闸门 2 的显式覆盖。

**A4 误操作面（推荐五道闸，全部可测）**

| # | 闸门 | 机制 | 可测面（CI） |
|---|---|---|---|
| 1 | **显式两阶段提交** | `*.prepare` 返回 `{confirmToken, summary}`（目标 id/尺寸/现有分区摘要/将写字节/不可逆告警）→ UI 强制用户确认（默认要求输入设备名末 4 位）→ `*.commit` 带 token。token **一次性 + 绑定 deviceId+操作 + 短过期（60s）** | 无 token / 错 token / 重放 / 过期 / 跨设备复用 五臂全拒 |
| 2 | **系统盘默认拒写** | 目标是系统/引导盘（含挂载中的根文件系统所在盘、Windows 系统卷、macOS 启动盘）⇒ 拒；仅 CLI `--allow-system-disk` / GUI 二次确认可覆盖 | 假挂载表注入单测 + 环回真值断言 |
| 3 | **同源硬拒且 fail-close** | 写回镜像到介质时，目标 = 该镜像的来源设备 ⇒ 拒。**写路径一律 fail-close**（与导出侧 -32006 的 sysfs 解析失败 fail-open **方向相反**：判定不了就不写） | 判定失败注入 ⇒ 断言拒绝而非放行 |
| 4 | **写前撤销快照** | 扇区写：原扇区先落 XDG state 撤销栈（保留最近 N 次/M 天）→ 快照不可写 ⇒ **拒写**；支持 `sector.undo`。镜像恢复粒度覆盖不了整盘，改由 `prepare` 摘要承担（列目标盘现有分区/前 512B 签名） | 快照失败 ⇒ 断言拒绝；undo 回读逐字节比对 |
| 5 | **审计（只增不改）** | 每次设备写落 JSONL：`ts/uid/op/deviceId/offset/len/undoId/result` + stderr 留痕 | 落盘行数/字段断言 |

**A5 与既有 -32006 缺口的关系（M5 准入条件）**

写场景把既有缺口的后果从「数据落到同盘另一处（可挽救）」升级为「**整盘覆写（不可挽救）**」：

- **Windows**：无 `st_rdev` ⇒ 同盘/同源判定整体失效（security §8）→ M5 前必须补卷句柄盘号比较。
- **macOS**：整盘源 vs 分区目标不拦 + 无 sysfs 兜底（security §9）→ M5 前必须补 IOKit 盘/分区归属。
- 结论：§4 依赖 D1 从"改进项"升格为**"M5 开工前必须闭合"**；未闭合前 M5 的写回功能
  只能对**镜像文件目标**开放（制作/校验/扇区编辑镜像不受影响）。

### B. 镜像格式与校验

- **格式（推荐）**：**raw（逐字节，dd 兼容）** 为唯一写入格式——零格式风险、可被
  `ddrescue`/`mmls`/取证工具链直接消费；稀疏文件（`.sparse`）**只读识别**不做写；
  E01/AFF 等取证封装**不做**（许可 + 复杂度，YAGNI；记为专业版后续方向）。
- **分区镜像**：统一用「设备 + 区间 `(offset, length)`」模型（整盘 = 全长），
  分区节点的选择只是 UI 便利（从分区表读取区间，避免依赖平台的 `sdb1`/卷命名差异）。
- **校验**：随镜像产出**伴生文件** `<img>.json`（元数据：源设备 id/尺寸/区间/坏道图/
  镜像字节数/时间/版本）+ `<img>.sha256`（`sha256sum` 格式，与系统工具互操作）。
  需新增依赖 `sha2`（工作区目前零哈希依赖，且团队对新增依赖有既往克制记录 ⇒ 列为开放项 B1）。
- **坏道图（推荐必做）**：读取失败区间记录进伴生 `.json`（ddrescue 式 `badranges`），
  **跳过不中断**（`xd-device` 已有坏道跳过语义），完成时如实报告"镜像有 N 处未读区"。
- **断点续作**：v1 **不做**（取消 = 保留已写部分 + 落图；续作需要 map 驱动的重扫设计，
  列为 M5 后的增强，见开放项 B2）。

### C. 扇区编辑的边界

- **读**：`sector.read`（设备/镜像通用，偏移 + 分片，上限 1MiB——与 `fs.read` 同口径），
  UI 十六进制视图虚拟化渲染。**只读查看不需要任何新权限**。
- **写**：`sector.write.prepare/commit`（一次 ≤ N 扇区、必须扇区对齐），走 A1-A4 全套。
- **目标范围（开放项 C1）**：推荐 **v1 只对镜像文件开放写**（物理设备写需显式开启"危险模式"开关），
  理由是扇区编辑对物理设备的真实需求集中在分区表/引导区修复——**而修复的正确姿势是先制作
  镜像、在镜像上编辑、校验后再写回**（正好复用 M5 的镜像链路，且在写回前多一次人工核对点）。
- **正当用途定性（写进文档）**：修复引导区/分区表/FS 元数据。产品**不做**擦除/反取证预设、
  不做隐藏数据（设计 §9 风险 6 的延伸），审计只面向本机用户。

### D. 批量工单模型

- **工单 = 介质集合 + 每介质的动作链**（`扫描(quick|deep) → 筛选(质量/类型/删除态) → 导出`；
  可选 `制作镜像`/`校验镜像`）。**默认串行执行**（多盘并行 = 磁盘争用 + 违反"单写者"纪律），
  持久化到既有 SQLite（新表 `jobs`/`job_steps`），崩溃续跑复用既有检查点语义。
- 每介质独立报告 + 汇总；导出目标**逐工单显式指定**（沿用三重校验 + -32006）。
- 无新写面：批量只编排既有的扫描/导出（写文件）。

### E. GUI / CLI 形态与专业版门禁

- **GUI（推荐）**：同一 app 内新增「工具箱」入口 + **会话级专业模式开关**（默认关）；
  扇区编辑器为全屏路由（十六进制视图 + 偏移跳转 + **单一提交点**）；
  镜像/工单为列表+详情页。**不做**独立专业版 app（多一套签名/公证/更新成本，收益为零）。
- **门禁**：写模式开启需二次确认 + 醒目标识（窗口标题/横幅）；许可门接 M3 的激活机制
  （专业版付费点 = 镜像/扇区/批量，与设计 §7 M5「专业版」定位一致）。
- **CLI（推荐纳入 M5）**：新 crate `xd-cli`，直链 `xd-core`（不走 IPC，设计 §3.1 第 5 条）。
  命令族：`image create|verify|info|restore`、`sector read|write|undo`、`job run|list|report`。
  约定：stdout = 机器可读（JSONL/golden）、stderr = 日志、退出码分级（0 成功 / 1 业务失败 /
  2 用法错误，沿用 daemon 既有 2）。**CLI 是 M5 的 CI 主测试面**——写路径若只能靠 GUI 点，
  就无法进门禁；CLI 使环回设备写、确认令牌、审计、坏道图全部可在 CI 真跑。
  安全语义与 GUI **同一套**（两阶段提交 + 审计 + 撤销快照），不给 CLI 开后门。

## 2. 任务粗分解（7 项；每项开工前单独细化）

### T1 写面隔离底盘（无用户可见功能）
**范围**：`xd-device` 写模块 + 写类型（与 `BlockDevice` 零互转）；`xd-writer` 二进制骨架
（单次、单目标、参数纵深校验，参照 `privcheck` 的"参数不信任"立场）；**写面清单 CI 门禁** +
daemon 符号级门禁；审计 JSONL 落盘与读取。
**出口判据**：写面结构断言与符号断言进 CI 且**对白名单外注入真红**（变异验证有牙）；
全仓既有只读门禁零回归；审计落盘单测。
**待细化**：白名单粒度（文件级 vs 函数级）；`xd-writer` 的 argv 契约与拒绝语义；
审计文件位置/轮转/权限位。

### T2 镜像制作 + 校验（低风险）
**范围**：`image.create`（设备+区间 → raw 文件，流式 4MiB 分块，进度通知）；坏道图；
伴生 `.json`+`.sha256`；`image.verify`（重算哈希比对）；`image.info`（读伴生/裸镜像探测）；
目标文件三重校验 + **-32006（镜像文件不得落在源设备上）**；取消语义（保留部分 + 落图）。
**出口判据**：合成镜像 e2e——制作 → 哈希与源逐字节一致 → 注入坏道夹具断言图与"跳过不中断"
→ **源哈希不变**（只读铁律门禁扩展）；镜像文件落在源设备 ⇒ 拒。
**待细化**：sha2 依赖裁定（开放项 B1）；坏道图的粒度与判定阈值；进度节流沿用 ≥250ms/≥1MiB。

### T3 镜像写回介质（高风险，首次设备写）
**范围**：`image.restore.prepare/commit`（两阶段 + 一次性令牌）→ writer 执行（A2/A3）；
尺寸校验（镜像 > 目标 ⇒ 拒，或显式覆盖；镜像 < 目标 ⇒ 保留余量不动）；可选写后校验；
`restore.cancel` 语义（半写如实报告）；`prepare` 摘要（目标现有分区/签名/挂载态）。
**出口判据**：**环回设备**（CI 免密 sudo 建 loop，沿用 e2e-loop 先例）写回 → 逐字节比对通过；
五臂令牌拒绝；系统盘/挂载盘拒写；同源 fail-close 断言；审计行断言；
（真机 U 盘写 = **未验证（需真机）**，出口手测）。
**待细化**：写后校验的默认开关与成本；`--allow-system-disk` 的 CLI 语义；
半写后的恢复引导文案；与 M2 的 -32006 补齐的对接验收（A5 准入）。

### T4 扇区编辑器（高风险）
**范围**：`sector.read` 分片读 + 十六进制视图（Flutter，虚拟化）；`sector.write.prepare/commit`
（对齐校验、单次上限）；**写前撤销快照** + `sector.undo`；镜像文件目标（默认）与
物理设备目标（危险模式开关，开放项 C1）。
**出口判据**：读分片边界（EEXIST 式偏移/越尾短读）单测；单扇区写 → 回读逐字节；
未对齐/越界/只读目标/快照失败 ⇒ 各拒；undo 使字节回到写前；审计落盘。
**待细化**：单次写上限（建议 ≤1MiB）；撤销栈容量与清理；hex 视图的渲染与编辑交互
（唯一点击提交、无快捷键直写）；"危险模式"的开启流程。

### T5 批量工单（编排，无新写面）
**范围**：工单模型 + SQLite 表 + 队列执行器（串行）+ `job.*` RPC + 通知；
筛选条件（质量/类型/删除态/大小）复用 `scan.results` 既有过滤语义；
逐介质报告与汇总导出（JSON + 文本）。
**出口判据**：多镜像夹具工单 e2e（建单→跑完→报告）；中途杀 daemon → 重启续跑（复用检查点）；
逐工单 -32006 断言；队列页 widget 测试。
**待细化**：工单的失败策略（遇错停整单 vs 跳过继续——建议可配，默认跳过并记录）；
是否支持导出模板（专业版后续）。

### T6 `xd-cli` 专业版命令行
**范围**：新 crate；命令族见 §1.E；复用 core 直链；JSONL stdout / 分级退出码；
`--yes`/`--confirm-token` 的非交互确认语义（**不得弱化**两阶段提交，只是把第二步交给脚本）。
**出口判据**：CI 全链路真跑（制作/校验/写回环回/扇区读写/工单），输出 golden 断言；
退出码矩阵断言；与 GUI 走同一 core 路径的对照测试（同一操作两入口行为一致）。
**待细化**：命令/子命令命名与参数（`--offset/--length/--device` 形态）；
脚本场景下的审计归属（uid 恒为调用者）。

### T7 出口验收
**范围**：全矩阵 CI（含环回写路径 job）；**写面清单终审**（全仓 grep + 符号检查双证）；
未验证边界总表新增 M5 章（真机设备写、真提权下写授权、真坏道盘、真 macOS/Windows 写路径）；
security 文档新增「设备写路径」章（与 §2 只读铁律的关系**正面写**）；
README/设计文档 M5 落点更新。
**出口判据**：见 §3。

## 3. 出口标准（M5 Done 的判据）

1. **写面可证**：CI 硬门禁两条（结构断言 + daemon 符号断言）绿，且对白名单外注入**真红**；
   `BlockDevice` trait 快照零写接口。
2. **只读铁律零回归**：既有"扫描/制作后源哈希不变"门禁在 M5 新增路径上**同样成立**。
3. **镜像链路**：制作 → 校验 → 写回 → 逐字节比对，全链路进 CI（环回设备），含坏道图与取消。
4. **写路径五道闸全可测**：令牌五臂、系统盘拒写、同源 fail-close、撤销快照、审计落盘。
5. **扇区编辑**：读/写/undo 全链真跑；四类拒绝臂（未对齐/越界/只读/快照失败）各有测试。
6. **批量工单**：多介质 e2e + 崩溃续跑；逐工单 -32006 断言。
7. **CLI**：命令族 golden + 退出码矩阵 + 与 GUI 同路径对照。
8. **文档**：security 新增设备写路径章（含"哪些平台未验证、后果是什么"）；
   未验证边界总表补 M5 全集；README/设计文档同步。
9. **跨平台**：Linux 写路径 CI 真跑；Windows/macOS 写路径编译 + 单元/冒烟，
   真机写**明确标注未验证**；A5 准入（M2 的 -32006 补齐）已闭合或写回功能按 A5 收窄。

## 4. 风险与依赖

| # | 风险/依赖 | 对策 |
|---|---|---|
| R1 | **只读铁律被侵蚀**（写能力从恢复路径被触达） | 裁定 A0-A1：类型隔离 + 写面 CI 门禁 + 符号门禁；评审时"不可达性"作为独立验收项 |
| R2 | **误写目标盘毁数据**（产品级不可逆事故） | A4 五道闸；写路径 **fail-close**（与导出 fail-open 相反）；真机手测清单 |
| R3 | **既有 -32006 缺口在写场景升级为整盘覆写** | §1.A5：M2 补齐为 **M5 准入条件**；未闭合前写回只对镜像文件开放 |
| R4 | **提权面扩大**（首次出现 root 写路径） | 长命 daemon 不写（独立 writer）；writer 不主动提权；平台必需 root 时叠加全部闸门 + 文档明示 |
| R5 | **半写状态**（恢复/扇区写中途取消/掉电） | 半写如实报告 + 引导文案；扇区级有撤销快照；大范围半写不假装"未发生" |
| R6 | **镜像格式/互操作性** | raw 唯一写入格式；伴生 `.json`+`.sha256`（标准工具可验）；稀疏/E01 不做 |
| R7 | **新增依赖**（哈希） | sha2（互操作优先）；列为开放项 B1 由 lead 裁定；不得因此引入哈希之外的依赖 |
| R8 | **合规/双刃性** | ToS 已有（设计 §9.6）；文档写明正当用途（引导区/分区表/元数据修复）；不做擦除/反欺骗/隐藏数据预设；审计面向本机用户 |
| R9 | **打包面**（多一个 writer 二进制） | 与 xd-daemon 同布局（同目录/`Contents/MacOS`）；签名归属随 M2 签名轮；冒烟脚本加一枚断言 |
| R10 | **团队/依赖顺序** | M5 不排期（设计 §7）；若在 M4 后落地，写路径**直接采用 M4 的 fd 化 + `openat2`** 设计，不得复刻 M1 的路径式打开（security §4/§6 残窗） |

**依赖**：D1 = M2 的 -32006 平台补齐（**准入条件**，A5）；D2 = 既有 `export_worker` 降权模式与
`check_on_source_at`（复用而非重写）；D3 = `store.rs` 持久化与检查点（工单复用）；
D4 = 现有扫描/导出事件流（通知模型复用）；D5 = M3 许可（专业版门，可后置）。

## 5. 开放项（需产品决策，冻结后才可进入细化轮）

| # | 开放项 | 建议默认 |
|---|---|---|
| O1 | 扇形编辑是否允许直接写**物理设备**（vs 仅镜像文件） | 默认仅镜像；物理设备写 = 危险模式显式开启 |
| O2 | 镜像恢复到更小的目标盘 | 拒绝；显式覆盖需二次确认 + 明示截断 |
| O3 | 写后校验是否默认开启 | 扇区写默认开启（便宜）；整盘写默认关闭（成本=再读一遍） |
| O4 | 哈希算法/依赖（B1） | sha2 + `sha256sum` 格式伴生文件 |
| O5 | 镜像断点续作（B2） | M5 不做，落 M5+ 增强 |
| O6 | 专业版门禁形态（许可/免费额度） | 接 M3；M5 先做会话级专业模式开关 |
| O7 | 审计保留策略（时长/清理/导出） | 默认保留最近 N 次 + 可导出；不自动上报（隐私） |
| O8 | 与 M4 的顺序 | M5 排 M4 后；若并行则 writer 自带 fd 化打开 |

`-32017` 撤销快照不可写（拒写）。
